# Phase 7CX Screen 4 Comparative Review Contract

## Purpose

7CX-B makes Screen 4 safer before any comparative visualization or adapter work. Screen 4 may show prepared comparison context, but it must not show comparative evidence, labels, graphics, or conclusions until a strict backend-generated deterministic comparison output contract is present.

Target A/B setup from Screen 2 is prepared comparison context only. It is not deterministic comparison output.

## Evidence Categories

Single AWR evidence is selected-scope deterministic evidence for one AWR/run. It may support Screen 3 diagnosis and Screen 4 single-scope display, but it is not A/B output.

Same-DB historical evidence is deterministic multi-snapshot or historical-window evidence for the same database context. It may support Historical Review, but it is not Target A/B output.

Prepared comparison context is Target A/B identity, mode, scope, window, and preparation status from Screen 2, Screen 3, route state, or continuity state. It can be displayed as preparation only.

Deterministic comparison output is a strict Screen 4 contract generated by the deterministic engine. It is the only source that can make Comparative Review output-ready.

Fleet or population evidence requires its own fleet/population evidence contract. Screen 4 must not render fleet diagrams from page identity, target selections, or ordinary comparison output.

Cache-only evidence is not evidence. Browser cache and route state may restore continuity only and cannot create current truth.

The word comparison is reserved for prepared Target A/B context, deterministic comparison output, Comparative Review state names, and explicit future comparison visualizations. Historical RAC, Data Guard, topology, period, and baseline copy should use supporting context, historical supporting context, topology supporting context, RAC supporting context, Data Guard supporting context, period context, or broader historical context. Target A/B preparation alone does not make Screen 4 comparison evidence ready.

## Comparative Review States

`comparison_unavailable` means no useful prepared comparison context and no validated deterministic comparison output exists. Allowed wording: no prepared comparison context is available. Allowed next action: prepare Target A/B context upstream. Graphics are forbidden.

`comparison_prepared_only` means Target A/B or comparison setup exists, but no validated deterministic comparison output exists. Allowed wording: prepared comparison context exists, Target A/B selections are preparation only, and deterministic comparison output is required before Screen 4 can show comparative evidence. Graphics are forbidden.

`comparison_evidence_required` means targets are selected, but required persisted or structured evidence is missing. Allowed wording: persisted structured evidence is required before comparison output can be requested. Graphics are forbidden.

`comparison_output_required` means target evidence or backend metadata suggests a comparison could be run or returned, but Screen 4 has not received a valid deterministic comparison output contract. Allowed wording: comparison-ready evidence has not been returned to Screen 4. Graphics are forbidden.

`comparison_output_ready` means a strict deterministic comparison output contract validates successfully. Screen 4 may display contract-backed comparative evidence only. Graphics remain forbidden unless the specific visualization is listed in `allowed_visualizations`.

## Strict Deterministic Output Contract

The future Screen 4 contract shape is:

```json
{
  "screen4_contract_type": "deterministic_comparison_output",
  "comparison_id": "required",
  "baseline_run_id": "required",
  "candidate_run_id": "required",
  "source_scope": "single_awr | same_db_historical | fleet | population | prepared_context",
  "comparison_scope": "target_a_vs_target_b | period | run | report",
  "generated_by": "deterministic_engine",
  "generated_at": "ISO-8601",
  "deterministic_engine_version": "required",
  "metric_deltas": [],
  "domain_deltas": [],
  "evidence_rows": [],
  "confidence_basis": {
    "basis_type": "deterministic_evidence",
    "sample_count": 0,
    "limitations": []
  },
  "missing_evidence": [],
  "allowed_visualizations": []
}
```

`metric_deltas` and `domain_deltas` may be empty when the contract explicitly carries valid deterministic no-change or empty-evidence evidence. Empty output must include either `evidence_rows` or an explicit deterministic empty-evidence explanation such as `no_change_evidence`.

`generated_by` must be `deterministic_engine`. LLM wording, browser state, route state, cache state, loose artifact references, and client-created output-ready flags are never sufficient.

## Rejections

Screen 4 must reject as output-ready:

- `None`, an empty mapping, or a string artifact reference.
- `comparison_artifact_reference` alone.
- `comparison_screen4_handoff` alone.
- Loose `comparison_result_*` fields.
- `selectedComparisonTargetA`, `selectedComparisonTargetB`, selected baselines, selected mode, or selected window.
- Route-only or cache-only state.
- Screen 2 Target A/B prepared context.
- Screen 3 `comparison_prepared_only` context.
- 7CC metadata unless a future adapter creates the strict Screen 4 contract.
- Client-created artifact-ready or output-ready claims.
- Contracts missing required identifiers, `generated_by`, `generated_at`, `deterministic_engine_version`, `confidence_basis`, or `allowed_visualizations`.
- Target identity mismatches when prepared Target A/B context is available.

## Graphics Guard

`allowed_visualizations` controls graphics. Even in `comparison_output_ready`, Screen 4 may render only visualizations explicitly listed in that contract.

Before `comparison_output_ready`, Screen 4 must render no comparison charts, comparison violins, distribution graphics, fleet/population diagrams, or A/B graphical summaries.

Fleet or population visualization names require both `allowed_visualizations` and a valid fleet/population evidence contract.

## LLM Boundary

LLM wording may explain validated deterministic comparison output only after that output exists. It cannot create comparison truth, choose the winning target, assign output readiness, create deltas, infer evidence, mutate runtime state, or replace the deterministic engine.

## 7CC Boundary

The 7CC comparison execution artifacts and references are not automatically Screen 4 output-ready. They require a future adapter that emits this strict Screen 4 deterministic comparison output contract before Screen 4 can render comparative evidence.

## 7CX-D Adapter Boundary

7CX-D introduces a backend-only adapter in `src/learning/screen4_comparison_contract.py`. The adapter may transform trusted 7CC/7AM comparison artifacts and governed workflow metadata into this strict contract, but only after Target A/B identity aligns, backend provenance is present, `generated_by=deterministic_engine`, `generated_at` is present, and deterministic evidence rows or deterministic empty-evidence explanation are available.

The adapter does not render charts, comparison violins, A/B overlays, or rich Comparative Review UI. It does not add browser-side comparison computation, browser artifact dereferencing, a Build Comparison button, or a Screen 4 provider route.

For 7CX-D, `allowed_visualizations` may include only conservative table/panel permissions when supported by fields: `metric_delta_table`, `domain_delta_summary`, `confidence_basis_panel`, and `missing_evidence_panel`. Distribution violins, time-series overlays, top-SQL movement, top-event movement, wait-class movement, and fleet/population visuals remain future and require additional deterministic evidence contracts.

## 7CX-G Visual Eligibility Boundary

7CX-G adds a deterministic eligibility layer for future comparative visuals. `allowed_visualizations` remains necessary but is not sufficient for graph or violin rendering. A future visual also requires the 7CX-G eligibility result to be `eligible`.

Time-series overlay eligibility requires explicit aligned time-series rows with timestamp, metric key, numeric Target A value, and numeric Target B value. Distribution/violin eligibility requires actual numeric Target A and Target B sample arrays or paired sample rows with at least three samples per target. SQL/event movement eligibility requires persistent SQL or event/wait identity and numeric Target A/B values.

Metric deltas, domain deltas, summary rows, route/cache state, prepared Target A/B context, LLM text, and snapshot identity are not sufficient visual evidence. 7CX-G does not render charts, violins, canvas/SVG, empty chart shells, fleet diagrams, or placeholder visuals.
